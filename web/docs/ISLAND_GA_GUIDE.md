# Island GA 使用指南 v2.2.0

## 🏝️ 什么是Island GA？

Island GA（岛屿遗传算法）是一种并行进化计算模型，将种群分成多个独立的"岛屿"，每个岛屿独立进化，并定期交换优秀个体。

### 核心优势
- ⚡ **并行加速**: 4核CPU可获得2-3倍性能提升
- 🌈 **多样性保护**: 多个独立种群避免过早收敛
- 🎯 **更好的解**: 不同岛屿探索不同区域
- 🔄 **参数多样性**: 每个岛屿使用略微不同的参数

---

## 🚀 快速开始

### 1. 选择Island GA
```
Algorithm Type → Island GA
```

### 2. 配置岛屿参数
```
Number of Islands: 4 (建议使用CPU核心数)
Migration Interval: 20 generations
Migration Size: 1 individual
Migration Topology: Ring (环形)
```

### 3. 点击Start
Island GA会：
1. 创建4个独立Worker线程
2. 每个岛屿独立进化
3. 每20代进行一次迁移
4. 自动追踪全局最优解

## 🎛️ 参数详解

### Number of Islands (岛屿数量)
```
范围: 2-8
推荐: 与CPU核心数相同

2核 → 2 islands (加速1.5-2x)
4核 → 4 islands (加速2-3x)
8核 → 4-6 islands (加速3-4x)

注意: 岛屿越多，通信开销越大
```

### Migration Interval (迁移间隔)
```
范围: 5-50 代
推荐: 10-20 代

小间隔(5-10): 频繁交流，收敛快，多样性低
中间隔(15-25): 平衡选择 ⭐
大间隔(30-50): 独立性强，多样性高，收敛慢
```

### Migration Size (迁移个体数)
```
范围: 1-5 个
推荐: 1-2 个

1个: 轻量迁移，保持独立性 ⭐
2-3个: 加速收敛
4-5个: 强耦合，接近单种群
```

### Migration Topology (迁移拓扑)
```
Ring (环形) ⭐
├─ 岛1 → 岛2 → 岛3 → 岛4 → 岛1
├─ 优点: 平衡，稳定
└─ 适用: 一般场景

Star (星形)
├─ 所有岛屿 ↔ 最优岛屿
├─ 优点: 快速传播优秀个体
└─ 适用: 快速收敛需求

Full (全连接)
├─ 所有岛屿两两交换
├─ 优点: 信息共享充分
└─ 适用: 多样性要求高
```

## 🔧 高级技巧

### 技巧1: 参数差异化
```
岛1: mutation=0.02, crossover=0.8
岛2: mutation=0.05, crossover=0.7
岛3: mutation=0.01, crossover=0.9
岛4: mutation=0.03, crossover=0.75
```

### 技巧2: 拓扑选择策略
```
早期: Full连接 - 快速共享
中期: Ring - 平衡探索与开发  
后期: Star - 向最优岛收敛
```

### 技巧3: 动态迁移
```
if (diversity < threshold) {
  增加迁移频率
} else {
  减少迁移频率
}

（当前版本固定间隔，未来可实现）
```

### 技巧4: 观察岛屿竞争
```
查看哪个岛屿最先找到解
→ 分析其参数配置
→ 应用到其他岛屿
```

## ⚠️ 注意事项

### 浏览器兼容性
- ✅ Chrome 80+
- ✅ Safari 14+
- ✅ Edge 80+
- ❌ IE不支持

### 性能考虑
- 岛屿数≤CPU核心数最优
- 迷宫<31×31不建议用Island GA（Worker开销大）
- 关闭"Show Exploration Process"以提升性能

### 内存使用
- 每个岛屿独立内存空间
- 4岛屿约占用~150MB
- 建议设备内存≥4GB

## 🐛 故障排除

### Q1: Island GA点击Start没反应？
**A**: 
- 检查浏览器Console是否有Worker错误
- 确认浏览器支持Web Workers
- 尝试减少岛屿数量到2

### Q2: 性能比Standard GA还慢？
**A**:
- 迷宫太小，Worker通信开销>计算开销
- 建议至少31×31以上使用Island GA
- 或增大种群到500+

### Q3: 岛屿显示不更新？
**A**:
- Worker可能崩溃，查看Console
- 刷新页面重新初始化
- 检查网络是否阻止Worker加载

### Q4: 内存占用过高？
**A**:
- 减少岛屿数量
- 降低种群大小
- 缩短历史记录保存长度

## 📚 技术原理

### 岛屿模型架构
```
Main Thread (UI)
    ↓
IslandGA Controller
    ↓
┌────┬────┬────┬────┐
│ W1 │ W2 │ W3 │ W4 │  ← Web Workers
└────┴────┴────┴────┘
  ↕️   ↕️   ↕️   ↕️
Migration (每N代)
```

### 迁移流程（Ring拓扑）
```
Gen 0-19: 各岛屿独立进化
Gen 20: 迁移
  W1最优 → W2
  W2最优 → W3
  W3最优 → W4
  W4最优 → W1
Gen 21-39: 继续独立进化
Gen 40: 再次迁移
...
```

### Worker通信
```
Main → Worker:
  - init: 初始化迷宫和配置
  - evolve: 进化N代
  - migrate: 接收外来个体
  - stop: 停止运行

Worker → Main:
  - generation: 每代结果
  - completed: 完成信号
  - error: 错误信息
```

## ✅ 最佳实践

### DO ✅
1. ✅ 大迷宫(>31×31)使用Island GA
2. ✅ 岛屿数=CPU核心数
3. ✅ 关闭"Show Exploration Process"提升性能
4. ✅ 使用Ring拓扑作为起点
5. ✅ 监控全局最优更新频率

### DON'T ❌
1. ❌ 小迷宫(<21×21)使用Island GA（开销大于收益）
2. ❌ 岛屿数>CPU核心数（性能下降）
3. ❌ 迁移间隔<5代（过于频繁）
4. ❌ 所有岛屿使用相同参数（失去多样性）
